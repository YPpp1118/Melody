## 1. 文档说明

### 1.1 目的

把“音乐数据库应用”从单一的资料管理工具，升级为一个完整的音乐产品：

- **能听**：浏览、检索、收藏、歌单、播放。
- **能玩**：4K 节奏演奏、每日挑战、排行榜、成长档案。
- **能装扮**：播放器和游戏界面支持用户自定义壁纸。
- **能管理**：后台维护曲库、谱面、用户与数据统计。

本文档同时作为产品、设计、开发和验收的共同依据。

## 2. 产品定位

### 2.1 一句话

**一个能听、能打、能装扮的音乐数据库应用。**

MelodyBase 以曲库为内容底座，以 4K 节奏演奏为差异化玩法，以“我的舞台”提供个性化表达，形成“发现音乐 → 演奏音乐 → 留下成绩 → 装扮空间 → 创作内容”的循环。

### 2.2 四层体验

| 层 | 用户价值 | 核心能力 |
| --- | --- | --- |
| 听 | 找到并收藏喜欢的音乐 | 曲库、搜索、歌单、收藏、播放、历史 |
| 玩 | 把喜欢的歌变成关卡 | 4K 演奏、每日脉搏、排行榜、成就、DNA |
| 装扮 | 让界面属于自己 | 播放器壁纸、游戏壁纸、上传与预设 |
| 管 | 保证内容持续更新 | 曲库 CRUD、谱面审核、用户管理、统计 |

### 2.3 目标用户

- **音乐爱好者**：浏览曲库、收藏歌曲、创建歌单。
- **轻度音游玩家**：不需要下载客户端，打开网页就能打一首歌。
- **核心音游玩家**：追求准确率、排行榜、幻影竞速与高难度谱面。
- **内容创作者**：制作谱面，让自己的关卡被其他人游玩。
- **管理员**：维护曲目、谱面、用户与运营数据。

### 2.4 设计原则

1. **音乐优先**：游戏与壁纸都服务于音乐，不喧宾夺主。
2. **低门槛、高上限**：4K + 三档难度让新手可玩，准确率与排行榜给高手空间。
3. **数据驱动**：BPM 筛选、节奏 DNA、谱面处方、成绩曲线都来自真实数据。
4. **公平可信**：服务端复算成绩，契约独立榜单，壁纸不影响判定。
5. **可读性优先**：播放器文字清晰，游戏音符清晰，任何壁纸都不能破坏可读性。
6. **轻量公平**：不做体力、抽卡、付费变强、强制每日登录惩罚。
7. **版权安全**：仅使用 CC0、自制或已授权音频，不内置商业歌曲。
8. **渐进交付**：先打通闭环，再扩展玩法与社交。

### 2.5 非目标

- 在线支付、会员订阅、广告、版权结算。
- 实时社交（评论、私信、关注）、直播。
- 推荐算法、AI 作曲或 AI 自动谱面。
- 音频转码、HLS 切片、DRM。
- 动态视频壁纸、壁纸商城、壁纸公开社区。
- 多租户、国际化多语言、原生移动 App。
- 首发不做实时多人联机。

## 3. 角色与权限

### 3.1 角色

| 角色 | 说明 |
| --- | --- |
| 游客 Visitor | 未登录访问者，可浏览公开内容 |
| 用户 USER | 注册用户，可收藏、建歌单、演奏、上传壁纸、创建谱面草稿 |
| 管理员 ADMIN | 维护曲库、审核谱面、管理用户、查看统计 |

> “谱面作者”不单独设角色，作为 USER 的能力：可创建草稿、试玩、提交审核，不能直接发布。

### 3.2 权限矩阵

| 能力 | 游客 | 用户 | 管理员 |
| --- | --- | --- | --- |
| 浏览曲库 / 搜索 / 公开歌单 | 允许 | 允许 | 允许 |
| 播放试听 | 允许 | 允许 | 允许 |
| 收藏 / 歌单 / 历史 | 禁止 | 允许 | 允许 |
| 4K 演奏 / 每日挑战 | 可试玩 | 允许计分 | 允许计分 |
| 上传成绩 / 上榜 | 禁止 | 允许 | 允许 |
| 上传私人壁纸 | 禁止 | 允许 | 允许 |
| 创建谱面草稿 | 禁止 | 允许 | 允许 |
| 提交谱面审核 | 禁止 | 允许 | 允许 |
| 发布 / 下架谱面 | 禁止 | 禁止 | 允许 |
| 曲库 CRUD | 禁止 | 禁止 | 允许 |
| 用户禁用 / 数据统计 | 禁止 | 禁止 | 允许 |

### 3.3 账户状态

- 密码使用 BCrypt 存储，不保存明文。
- 被禁用用户不能登录；已签发令牌在下一次校验时失效。
- 管理员账号由初始化数据创建，不开放前台注册。
- 用户只能修改自己的歌单、成绩、壁纸与谱面草稿。

### 4.3 核心用户旅程

**A. 新用户第一次体验**

```text
首页 → 浏览热门歌曲 → 点开演奏 → 选择 EASY → 完成一局
→ 结算评级 → 获得“初次登台”成就 → 注册并保存成绩
```

**B. 每日回访**

```text
首页今日脉搏 → 查看今日曲目与契约 → 一次计分演奏
→ 进入今日排行榜 → 查看“超过 92% 玩家” → 连续打卡 +1
```

**C. 个性化**

```text
全屏播放器“更换壁纸” → 上传图片 → 调整焦点/模糊/压暗
→ 保存 → 播放页生效 → 切换到游戏 Tab，设置另一张壁纸
```

**D. 内容生产**

```text
我的节奏 → 谱面工坊 → 选择歌曲 → 编辑音符 → 试玩
→ 提交审核 → 管理员通过 → 其他玩家可游玩
```

### 4.4 全局播放器

- 底部固定迷你播放器：封面、歌名、播放/暂停、上一首/下一首、进度、音量。
- 点击进入全屏播放器；切页不中断播放。
- 壁纸只作用于全屏播放页与歌词页，迷你播放器使用封面主色，避免性能浪费。
- 无音频 URL 的歌曲显示“暂无音源”，不进入自动连播队列。

## 6. 功能需求

### 6.1 账号与个人中心

- 注册：用户名 3–20 位且唯一，邮箱唯一，密码 8–32 位且包含字母和数字。
- 登录：用户名或邮箱 + 密码；连续失败 5 次锁定 10 分钟。
- 令牌：Access Token 15 分钟，Refresh Token 7 天；支持刷新与退出失效。
- 资料：昵称、头像；角色与状态不可自行修改。
- 个人中心：我的收藏、歌单、最近播放、演奏成绩、成就、节奏 DNA。
- 设置：播放器壁纸、游戏壁纸、音符速度、延迟校准、特效强度、音量。

### 6.2 曲库与发现

- 首页聚合：热门歌曲、最新专辑、流派入口、公开歌单、今日脉搏。
- 歌曲列表：封面、歌名、歌手、专辑、时长、BPM、流派、播放次数。
- 歌手详情：头像、简介、专辑、热门歌曲。
- 专辑详情：封面、发行日期、歌手、曲目列表。
- 流派：列表、流派下歌曲。
- 搜索：歌曲名、歌手名、专辑名；支持流派、BPM 区间、难度筛选。
- 排序：最新、最热、BPM、歌名。
- 统一分页：`page`、`size`（默认 12，最大 50）。
- 可演奏标识：有已发布谱面且有音源的歌曲显示“可演奏”。

### 6.3 播放、收藏、歌单、历史

**播放**

- 全局播放器跨页面持续播放。
- 全屏播放页展示封面、歌名、歌手、专辑、歌词、进度、音量、队列。
- 播放开始或超过 10 秒上报一次收听记录。
- 无音源时降级展示，不报错。

**收藏**

- 歌曲收藏/取消收藏，幂等。
- 收藏列表分页，展示歌曲信息与收藏时间。

**歌单**

- 每个用户最多 50 个歌单，名称 1–50 字，简介 500 字以内。
- 公开/私密；私密歌单仅本人可见。
- 添加/移除歌曲，重复添加幂等，支持排序。
- 删除歌单只删除关系，不删除歌曲。

**历史**

- 最近播放保留 100 条/人，按时间去重展示。
- 支持清空历史，不影响统计数据。

### 6.4 音律实验室

#### 6.4.1 基础设定

| 项目 | 规则 |
| --- | --- |
| 轨道 | 4K，键位 D / F / J / K |
| 音符 | Tap、Hold |
| 难度 | EASY / NORMAL / HARD，等级 1–15 |
| BPM | 单 BPM，30–300，不支持变速 |
| 速度 | 视觉速度 1.0×–3.0×，不影响判定 |
| 音频偏移 | 谱面偏移 + 设备校准偏移 |
| 生命值 | 标准模式启用，练习与每日挑战不失败 |

#### 6.4.2 判定与计分

| 判定 | 时间窗 | 权重 | 连击 | 生命 |
| --- | --- | --- | --- | --- |
| PERFECT | ±45ms | 1.0 | +1 | +1 |
| GREAT | ±90ms | 0.7 | +1 | 0 |
| GOOD | ±135ms | 0.4 | +1 | −2 |
| MISS | 超过 135ms 或未击打 | 0 | 断连 | −10 |

计分：

```text
accuracy = (PERFECT × 1.0 + GREAT × 0.7 + GOOD × 0.4) / noteCount
score = floor(900000 × accuracy + 100000 × maxCombo / noteCount)
```

- 全 PERFECT 全连为 1,000,000。
- 服务端根据判定计数与谱面音符数复算，不能直接信任客户端总分。
- 评级：MAX 1,000,000；S+ ≥990,000；S ≥950,000；A ≥900,000；B ≥800,000；C ≥700,000；D 更低。
- Hold 头部按上表判定，提前松手超过 150ms 尾判窗记 MISS。
- 输入在 ±135ms 外忽略；音符过窗自动 MISS。

#### 6.4.3 演奏流程

```text
选歌 → 选谱面/难度 → 延迟校准检查 → 倒计时
→ 演奏 → 暂停/恢复 → 结算 → 上榜 → 成就 → 再试一次
```

- 开始前预加载音频、谱面、壁纸；壁纸超时不阻塞。
- 页面隐藏自动暂停；恢复时重新倒计时。
- 结算展示评级、分数、准确率、最大连击、判定分布、排名、个人最佳、成就。
- 排行榜按分数、准确率、最大连击、达成时间排序。

#### 6.4.4 每日脉搏

- 每天 00:00（Asia/Shanghai）刷新一首曲目和一条契约。
- 服务端用日期 + 契约 + 密钥做 HMAC 确定性选谱。
- 第一次计分尝试计入排行榜；之后可无限练习，不改变成绩。
- 评级 C 或以上计入连续打卡；每日挑战不启用生命值失败。
- 排行榜展示前 100 名与个人百分位；历史榜单可回看。
- 同一用户同一天只接受一条计分记录，重复提交幂等或返回冲突。

#### 6.4.5 契约挑战（P1）

| 契约 | 规则 |
| --- | --- |
| 标准 | 无额外限制 |
| 镜像 | 四条轨道左右互换 |
| 疾走 | 视觉速度 +25% |
| 隐匿 | 音符在判定线前 350ms 淡出 |
| 背水 | 任何 MISS/GOOD 立即失败 |
| 无 HUD | 隐藏分数、连击、准确率 |

- 每种契约独立排行榜和最佳成绩。
- 不提供分数倍率，避免排行榜通胀。
- 每日脉搏每天轮换一条契约。

#### 6.4.6 幻影竞速（P1）

- 可选择个人最佳或经授权的公开成绩作为幻影。
- 幻影采样进度、分数、连击，5Hz，最多 6000 点。
- 进度条与分段超越提示；不计入正式排行榜。
- 默认仅本人可见；公开幻影需用户主动开启。

#### 6.4.7 节奏 DNA（P1）

六维：准度、速度、稳定、耐力、读谱、多面。

- 取最近 30 条有效成绩计算；少于 5 条显示“样本不足”。
- 展示雷达图、BPM 舒适区、最强/最弱轨道、30 天活动热力图。
- 谱面处方：根据短板推荐 3 张谱面并说明理由。
- 缓存 10 分钟，成绩更新后失效。

#### 6.4.8 谱面工坊（P1）

- 波形时间轴、BPM/偏移、1/4–1/16 网格。
- 放置/删除 Tap 与 Hold，拖拽、框选、复制、撤销/重做。
- 从任意位置试玩，自动保存草稿。
- 只能绑定曲库已有歌曲，不能上传音频。
- 发布流程：草稿 → 审核 → 发布/驳回；管理员审核。
- 校验：音符数 10–5000、时间递增、Hold 不重叠、时长 100ms–20s、音频范围内。
- 发布后修改自动生成新版本，旧版本可回滚。

#### 6.4.9 成就（P0 基础 / P1 完整）

- 初次登台、全连新星、完美主义、百炼成钢、手速觉醒、节拍器、七日脉搏等。
- 成就只增不减，不可重复解锁；进度持久化。
- 个人主页可展示 3 枚精选徽章。
- 不做每日登录奖励与在线时长奖励。

#### 6.4.10 战绩卡（P1）

- 结算页生成 1080×1440 PNG，含封面、曲名、难度、评级、分数、准确率、连击、DNA 迷你雷达。
- 支持下载与分享链接；隐私可设为公开、仅链接可见、关闭。

#### 6.4.11 探索模式（P2）

- 音浪首领：Boss 血量与阶段演出，不改变谱面判定。
- 段位试炼：每月三张固定谱面，5 次机会，结算段位。
- 同屏协作：四轨拆分为两人，共同生命值。
- 社区谱面市场：评分、收藏、精选、举报。

#### 6.5.3 上传与调整

- 支持 JPEG / PNG / WebP，单文件 ≤ 10MB。
- 建议尺寸 ≥ 1280×720；允许竖图，通过焦点裁切。

- 每人最多 20 张、总容量 100MB。
- 生成桌面、移动、缩略图三个版本；剥离 EXIF。

#### 6.5.4 游戏安全边界

- 舞台背景叠加强制暗层与轨道暗槽。

- 演奏时可选择隐藏壁纸。
- 壁纸不影响判定、分数与公平性。
- 只支持静态图片，拒绝 SVG/GIF/视频。

#### 6.5.5 隐私与性能

- 上传壁纸默认私有，通过鉴权接口读取，其他用户不可访问。
- 播放器、游戏双端同步；删除使用中的壁纸自动回退默认。
- 壁纸加载超时 800ms 则降级，不阻塞播放或演奏。
- 游戏背景只渲染一次，不进入每帧循环。

## 7. 跨模块业务规则

1. 歌曲必须关联一个歌手；专辑与流派可选。
2. 谱面必须绑定已存在的歌曲；只有拥有已发布谱面且有音源的歌曲才标记为“可演奏”。
3. 删除歌手/专辑/流派前必须检查引用；存在引用时返回 409。
4. 歌单歌曲唯一 `(playlist_id, song_id)`；收藏唯一 `(user_id, song_id)`。
5. 游戏成绩与收听记录分开：`play_record` 记录听歌，`game_record` 记录演奏。
6. 每日挑战只接受一次计分尝试；练习成绩不影响榜单。
7. 排行榜成绩以服务端复算为准；客户端提交的分数不可直接采信。
8. 游戏壁纸必须经过安全遮罩；播放器壁纸必须有可读性遮罩。
9. 私有图片和壁纸必须鉴权读取；公开资源与私有资源使用不同路径。
10. 用户上传图片只接受静态 JPEG/PNG/WebP；音频仅管理员上传。
11. 所有时间统一 UTC 存储，API 输出 ISO-8601，前端按 `Asia/Shanghai` 展示。
12. 用户删除账号时，私有壁纸、歌单、成绩按隐私策略清理；公开谱面保留作者署名或转为官方归档。

### 8.3 关键字段与约束

**song 扩展**

- `bpm DECIMAL(6,2)`、`energy TINYINT`、`audio_url VARCHAR(500)`、`is_playable BOOLEAN`。
- 可演奏 = 有已发布谱面 + 有音源。

**chart**

- 关键字段：`song_id`、`creator_id`、`difficulty`、`level`、`bpm`、`offset_ms`、`duration_ms`、`lane_count`、`note_count`、`chart_data`、`chart_hash`、`status`、`version`。
- 状态：DRAFT / REVIEW / PUBLISHED / REJECTED / OFFLINE。
- 索引：`(song_id, difficulty, status)`、`(status, level)`。

**game_record**

- 关键字段：`client_record_id`、`user_id`、`chart_id`、`score`、`accuracy`、`max_combo`、四项判定计数、`grade`、`modifiers`、`lane_stats`、`replay_data`、`is_scored`、`played_at`。
- `client_record_id` 唯一，保证提交幂等。
- 记录不可变；修正通过新记录完成。

**chart_best**

- 唯一 `(user_id, chart_id, modifier_key)`。
- 冗余 score / accuracy / max_combo，排行榜优先查询此表。

**user_wallpaper_setting**

- 联合主键 `(user_id, scope)`，scope 为 PLAYER / GAME。
- 字段：`source`、`preset_key`、`asset_id`、`fit`、`focal_x`、`focal_y`、`zoom`、`blur_px`、`dim_percent`、`stage_dim_percent`、`show_during_play`。
- 删除 asset 时，引用它的设置重置为默认。

**通用约束**

- 用户名、邮箱、流派名唯一。
- `(playlist_id, song_id)`、`(user_id, song_id)` 唯一。
- 每日挑战 `challenge_date` 唯一；每日计分尝试按用户唯一。
- 壁纸 `(user_id, checksum)` 唯一，重复上传复用。

### 8.4 谱面 JSON

```json
{
  "schemaVersion": 1,
  "laneCount": 4,
  "bpm": 174,
  "offsetMs": 320,
  "notes": [
    { "t": 1200, "lane": 0, "type": "tap" },
    { "t": 1500, "lane": 2, "type": "hold", "durationMs": 620 }
  ]
}
```

- `t` 为相对音频起点的毫秒数。
- 服务端按时间排序并计算 SHA-256，客户端校验哈希。

### 8.5 数据生命周期

- 成绩、每日尝试、收藏保留至用户删除或管理员按规则清理。
- 播放历史保留最近 100 条/人。
- 壁纸删除后异步清理对象存储；失败进入补偿队列。
- 谱面下架后不再出现在列表与每日候选，历史成绩保留。
- 用户注销后，私有数据清理；公开内容去标识化或归档。

### 10.5 关键实现

**认证**

- Access Token 短期，Refresh Token 长期。
- 前端内存/会话存储 Access Token，刷新令牌使用安全 Cookie。
- 路由守卫只优化体验，后端方法级授权是最终防线。

**音频与游戏循环**

- 使用 `AudioContext.currentTime` 作为唯一时间源，不用 `setInterval`。
- rAF 只负责绘制；判定时间来自音频时钟。
- Canvas 绘制、对象池、可视窗口裁剪；2000 音符目标 60fps。
- 页面隐藏自动暂停；蓝牙耳机通过校准缓解延迟。
- 倒计时基于音频时钟，避免切后台不同步。

**成绩防作弊**

1. 登录 + 演奏令牌绑定用户、谱面、哈希、有效期。
2. 服务端复算分数，校验计数总和、连击、局时与频率。
3. `client_record_id` 幂等，网络重试不重复。
4. 每日挑战只接受一次计分。
5. 明确边界：MVP 防随手改分，不承诺防专业外挂；回放验证为 P2。

**每日挑战**

- Spring `@Scheduled` 每天 00:00 Asia/Shanghai 生成。
- HMAC 选谱，数据库唯一约束保证幂等。
- 候选必须已发布、音频可播放、音符数足够。

**排行榜**

- 读 `chart_best`，排序 `score DESC, accuracy DESC, max_combo DESC, updated_at ASC`。
- 每日榜单由 `daily_attempt` 限定。
- 数据量增大后加 Redis ZSET 或本地缓存。

**图片与壁纸**

- 上传校验大小、MIME、像素与实际解码；剥离 EXIF。
- 生成 display / mobile / thumb 三版；计算主色与亮度。
- 私有文件不走公开静态目录；鉴权读取或短时签名。
- 前端用 Blob URL + 缓存；退出登录统一释放。
- 游戏背景一次性绘制，模糊不进入每帧；加载超时降级。

## 14. 风险与待确认事项

### 14.1 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 范围过大 | 延期 | 锁定 P0，P1/P2 后置；4 周 Demo 先验证核心 |

| 移动端触控延迟 | 高难度不可玩 | Pointer Events、全屏、低延迟渲染 |
| 音游内容不足 | 玩法空洞 | 首发 6–10 张测试谱；工坊后续补内容 |
| 成绩作弊 | 榜单失真 | 令牌、复算、幂等、频率限制；回放验证后续 |
| UGC 审核压力 | 违规内容 | 先管理员发布，开放投稿后加审核队列 |
| 壁纸性能 | 掉帧/卡顿 | 降采样、预加载、一次性绘制、超时降级 |
| 壁纸可读性 | 音符看不清 | 强制安全遮罩、亮度检测、限制压暗下限 |
| 图片安全 | XSS/存储滥用 | 拒绝 SVG、MIME 与解码校验、配额、鉴权 |
| 版权 | 法律风险 | 只用 CC0/授权音频；禁止用户上传音频 |

| 问题 | 建议默认值 |

MVP 先证明“能听、能打、能上榜、能换壁纸”的闭环；等手感和留存成立，再投入 DNA、幻影、工坊与赛季，而不是一开始就把所有玩法堆满。
